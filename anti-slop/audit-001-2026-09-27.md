# antislop audit 001

Date: 2026-09-27
Scope: whole site, UI and logic. Mode 2 (audit an existing project).
Direction: `DESIGN.md`, extracted from code the same day. Dials `ENERGY 2 / RHYTHM 2 / MOTION 1`.
Verified against: `src/`, a production build, and the running dev server at 375x812 and 1280x800.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## HIGH

### 1. Heatmap reports "0 contributions" next to 17 colored cells (R-17, C-5)

`OpenSource.tsx:136-137` sums `contributions[].count`, but `scripts/fetch-github.ts`
only fills `count` on the GraphQL path. Without `GITHUB_TOKEN` it falls back to an HTML
scrape that records `level` and leaves `count: 0`. Measured in the browser: 378 cells,
17 visibly colored, header reads `0 contributions` and `0 active days`, and every
colored cell's tooltip reads `<date>: 0 contributions`. A visitor can see the
contradiction. Numbers presented as fact that are not.

### 3. Fourteen tap targets below 44px on mobile (R-03)

Measured at 375x812. Nav links 47x27, theme toggle 26x26, footer social icons 16x16,
the `@LvnnnX` profile link 51x18, contact tiles 42px tall. The footer icons are the
worst: a 16px target is a quarter of the minimum area.

### 4. `100vh` on mobile (R-03)

`src/index.css` (`body`, `#root`), `case-study.css` `.cs`, `planned.css`, and
`ServicesPage` all use `100vh` or `min-h-screen`. On mobile browsers `100vh` includes
the retractable chrome, so the element is taller than the visible area. `portfolio-hero`
compounds it by nesting `min-h-screen` inside `min-h-screen`.

### 5. Thirty-three em dashes in UI text and comments (R-02)

Including visitor-facing strings: the hero subtitle, the accessible `h1`, the SEO title,
and several `ServicesPage` tier descriptions. `TechNewsIndexPage:31` also uses an em dash
as a missing-date glyph.

### 6. Three data views have no empty state (R-27)

`Experience`, `Projects`, and `Skills` map over JSON with no `length === 0` branch. They
render nothing at all if the array empties, with no explanation. The three index pages
already handle this correctly, so the pattern exists in the codebase and was not applied
here.

### 7. Hero claims "8+ Production Deployments" with nothing to check it against (R-17)

`portfolio-hero.tsx:170`. The site publishes 7 projects, of which 1 carries a live URL.
The claim may well be true, but nothing on the page supports it, which is exactly the
shape R-17 rejects. `4+ Years Coding` and `3.98 GPA` are the owner's own facts and stay.

## MEDIUM

### 8. Eight uppercase labels with wide tracking, no written reason (R-06)

`tracking-[0.12em] uppercase` on stat labels and section eyebrows. The pattern is
allowed, but the reason has to be written down, and it was not.

### 9. Event glyphs chosen without a written relevance (R-04)

`OpenSource.tsx:75` maps event types to `↳ + ⑃ ★ ⇄ ◉`. `⑃` (U+2443) and `◉` are outside
most UI font coverage and fall back to a box on Windows. The mapping is relevant but
undocumented, and two of the glyphs do not render reliably.

## Addendum, found during the fix pass

### 13. `/services` never got the flat-surface treatment (R-10, R-01, R-12)

HIGH. `services.tsx` applies `backdrop-blur-2xl` to all six `GlassCard` instances plus
`backdrop-blur-xl` to the secondary CTA: seven blurred elements against a dose cap of one
to two. Each card also carries a decorative hairline gradient strip, and the featured
variant adds a gradient fill and a 80px clay-tinted glow shadow.

The blur is technique with no effect, not just technique without purpose: the cards sit on
flat paper with no imagery behind them, so `backdrop-filter` composites an extra layer and
blurs nothing a visitor can see. The component is still named `GlassCard`, which is the
same stale-name trap that left `liquid-glass` referenced after its CSS was deleted.

This is the one page the earlier "strip AI slop" pass missed, and it contradicts the
flat-surface rule in `DESIGN.md`.

### 14. Hero text depends on an IntersectionObserver callback that can never arrive (C-4, R-19)

HIGH. `BlurText` in `portfolio-hero.tsx` starts every letter at `opacity: 0` and only
reveals them when an `IntersectionObserver` reports the paragraph as intersecting. The
observer fires once, and if that first callback reports the element as not intersecting,
no second callback ever arrives, because the intersection never changes afterwards. The
name then stays invisible for the life of the page.

Reproduced in the preview pane: the site's own name renders as a faint ghost while the
non-animated stat row beside it renders normally. The visible headline of the site is the
element most dependent on an animation completing.

Fixed by settling the initial state from `getBoundingClientRect()` on mount and keeping
the observer only for elements that genuinely start off screen.

### 15. Heatmap grid dropped 300 of 365 days (C-4, R-17)

HIGH, found after delivery. The fix in finding 1 made the header honest but left the grid
itself broken, and the evidence was already in the first click-through (12 coloured cells
against 88 active days) without being followed up.

`OpenSource.tsx` grouped days into columns by walking the array and starting a new column
on every Monday, then rendered each column's first seven entries by position. The scrape
returns cells in the calendar's row order (every Sunday, then every Monday), so 53 Sundays
landed in one column, each Monday opened a column of one, and the remaining 261 days piled
into the last column. Measured on the same data: 65 of 365 days rendered, 12 of 88 active.

Two fetcher faults compounded it. `main()` kept the old snapshot only when profile, repos
and activity all failed, so a failed contributions request alone overwrote a year of data
with `[]` and hid the heatmap. Scrape results were also written unsorted.

Fixed: `sections/heatmap.ts` places each day by date arithmetic (UTC weekday for the row,
weeks since the grid start for the column), independent of input order. Verified against
the real data in scrape order, chronological order and shuffled order: 365 of 365 placed,
88 of 88 active, every cell on its weekday row. The fetcher now returns `null` on failure,
falls back per field to the committed snapshot, and sorts contributions before writing.
